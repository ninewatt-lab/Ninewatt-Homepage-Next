# 콘텐츠 시트 운영 가이드

홈페이지 콘텐츠 일부를 개발자 배포 없이 Google Sheet에서 관리하는 방법입니다.
현재 대상은 **미디어(뉴스·영상)** 한 컬렉션이며, 검증 후 순차로 넓힙니다.

## 왜 CMS가 아니라 시트인가

넘길 대상 대부분이 "행을 추가/삭제하는 표"라서 스프레드시트가 스키마와 그대로 맞습니다.
Payload CMS를 다시 붙이면 EC2(t3.small, 2GB)에 PostgreSQL 컨테이너가 추가되고,
Payload는 빌드 타임에 DB 연결을 요구하므로 GitHub Actions에도 임시 DB가 필요합니다.
월 2건 수준의 등록 빈도에 비해 운영 비용이 큽니다.

교체 지점은 [`src/lib/cms.ts`](../src/lib/cms.ts)의 게터 하나뿐이라,
나중에 CMS로 옮길 때 페이지 코드는 그대로 둘 수 있습니다.

## 홍보 담당자용 — 뉴스/영상 등록하기

### 시트 서식

한 시트(탭)에 뉴스와 영상을 함께 넣고 `type` 열로 구분합니다. **첫 행은 반드시 헤더**입니다.

| 열 | 필수 | 설명 |
|---|:---:|---|
| `type` | | `video` 또는 `영상`이면 영상 탭, 그 외(비워두거나 `article`)는 뉴스 탭. |
| `date` | ✅ | `2026.08.18` 형식. **형식이 다르면 그 행은 무시됩니다.** |
| `title` | ✅ | 국문 제목. |
| `title_en` | | 영문 제목. 있으면 영문/일문/불문 페이지에서 이 제목이 보입니다. 비우면 국문 제목이 그대로 나갑니다. |
| `origin` | | 매체명 (예: 전자신문). |
| `link` | ✅ | `http://` 또는 `https://`로 시작하는 원문 주소. |
| `image` | | 썸네일 주소. **유튜브 영상은 비워두면 자동으로 채워집니다.** |

- 열 순서는 바뀌어도 되고, 대소문자도 상관없습니다(`Title` = `title`).
- 빈 행은 무시되므로 중간에 여백을 둬도 됩니다.
- 같은 `link`가 두 번 있으면 **위쪽 행**만 남습니다.

> **작은따옴표로 시작하는 제목 주의.** Google Sheets는 셀 맨 앞의 `'`를
> "이 셀은 텍스트" 표시로 읽고 값에서 지웁니다. `'그린 리더십' 선봉에…` 처럼
> 따옴표로 여는 국문 헤드라인이 `그린 리더십' 선봉에…` 로 조용히 바뀝니다.
> 앞따옴표를 남기려면 셀에 **작은따옴표를 두 번**(`''그린 리더십' 선봉에…`) 치세요.
> `pnpm check:media`가 짝이 안 맞는 제목을 행 번호와 함께 알려줍니다.

### 처음 한 번: 시트 만들기

1. 새 Google Sheet를 만들고 [`docs/media-seed.csv`](media-seed.csv)(기존 101건)를 가져옵니다.
   - 파일 > 가져오기 > 업로드 > `media-seed.csv` > "현재 시트 바꾸기"
2. 서버가 읽을 CSV 주소를 정합니다. 둘 중 하나면 됩니다.

   **① 링크 공유 방식 (권장)** — 공유 > "링크가 있는 모든 사용자" 뷰어로 설정한 뒤:

   ```
   https://docs.google.com/spreadsheets/d/<문서ID>/export?format=csv&gid=<시트gid>
   ```

   편집이 곧바로 반영되고 별도 게시 단계가 없습니다. `gid`는 시트를 열었을 때
   주소창 `#gid=` 뒤의 숫자입니다. **`gid`를 반드시 붙이세요** — 생략하면 "첫 번째 탭"을
   읽으므로, 나중에 탭을 추가해 앞으로 옮기면 엉뚱한 표를 읽습니다.

   **② 웹에 게시 방식** — 파일 > 공유 > 웹에 게시 > 해당 시트 + 쉼표로 구분된 값(.csv):

   ```
   https://docs.google.com/spreadsheets/d/<문서ID>/pub?gid=<gid>&single=true&output=csv
   ```

   문서 자체는 비공개로 두고 선택한 시트만 공개할 수 있습니다. 대신 Google이 게시본을
   따로 캐시해서 반영이 몇 분 더 늦습니다.

   ①은 문서 전체(모든 탭)가 링크로 열람 가능해집니다. 어차피 공개될 보도자료 목록이라
   문제는 없지만, **비공개 정보를 같은 문서의 다른 탭에 두지 마세요.**

3. 정한 주소를 개발자에게 전달합니다. (서버의 `MEDIA_SHEET_CSV_URL` 환경변수)
4. 붙이기 전에 한 번 점검합니다 — 서버와 **같은 규칙**으로 검사하므로 여기서 통과하면 사이트에도 그대로 나옵니다.

   ```bash
   pnpm check:media '<게시된 CSV 주소>'
   ```

### 평소: 등록/삭제

행을 추가하거나 지우면 됩니다. **최대 10분 안에 홈페이지에 반영됩니다.**

즉시 반영이 필요하면 아래 주소를 브라우저에서 한 번 열면 됩니다(즐겨찾기 권장):

```
https://ninewatt.com/api/revalidate?tag=media&secret=<개발자에게 받은 값>
```

`{"revalidated":"media"}` 가 보이면 성공입니다.
그 다음 미디어 페이지를 **두 번** 새로고침하세요. 첫 요청은 옛 내용을 보여주면서
뒤에서 시트를 다시 읽고, 두 번째 요청부터 새 내용이 나옵니다.

### 잘못 입력하면 어떻게 되나

안전장치가 두 겹 있습니다.

1. **행 단위** — 날짜 형식이 틀리거나 제목·링크가 빠진 행은 그 행만 빠지고, 나머지는 정상 노출됩니다.
2. **전체 단위** — 시트를 통째로 지웠거나, 게시를 해제했거나, 네트워크가 끊기면
   **마지막으로 정상 조회된 시트 내용**이 그대로 유지됩니다. 서버가 재시작돼 그 기억마저
   없으면 마지막으로 배포된 [`src/data/media.ts`](../src/data/media.ts)로 떨어집니다.
   어느 경우든 **홈페이지가 빈 페이지가 되는 일은 없습니다.**

행이 빠졌다면 대개 `date` 형식(`2026.08.18`)이나 `link`의 `https://` 누락입니다.
어느 행이 왜 빠졌는지는 아래 명령으로 행 번호까지 확인할 수 있습니다(개발자에게 요청하세요).

```bash
pnpm check:media            # .env.local 의 주소를 사용
pnpm check:media '<주소>'   # 특정 시트를 지정
```

```
데이터 행 102개 중 101개가 사이트에 나옵니다.
  뉴스 77건 / 영상 24건
  영문 제목(title_en) 있음: 12건 — 없는 89건은 영문·일문·불문 페이지에 국문 제목이 나갑니다.

❌ 사이트에 나오지 않는 행 1개:
  38행: date 형식이 2026.08.18 이 아닙니다 (입력값: 2026-08-06)
```

## 개발자용

### 구성 요소

| 파일 | 역할 |
|---|---|
| [`src/lib/sheet.ts`](../src/lib/sheet.ts) | CSV 파서 + fetch/검증/폴백. 컬렉션 무관하게 재사용. |
| [`src/lib/media-schema.ts`](../src/lib/media-schema.ts) | 미디어 행 → `MediaItem` 규칙. **서버와 점검 스크립트가 공유**한다. |
| [`src/lib/cms.ts`](../src/lib/cms.ts) | `getMedia()` — 중복 제거, 로케일 제목 선택, 정렬. |
| [`src/app/api/revalidate/route.ts`](../src/app/api/revalidate/route.ts) | `revalidateTag` 호출용 엔드포인트. |
| [`scripts/check-media-sheet.mts`](../scripts/check-media-sheet.mts) | 시트 점검. `pnpm check:media [주소]` |
| [`scripts/export-media-csv.mts`](../scripts/export-media-csv.mts) | 정적 데이터 → 시트 서식 CSV. `pnpm export:media` |

행 파싱 규칙을 `media-schema.ts`로 뺀 이유는 점검 스크립트가 규칙을 복제하면
"스크립트는 통과했는데 사이트엔 안 나온다"가 생기기 때문입니다. 규칙을 바꿀 때는
이 파일만 고치면 양쪽에 반영됩니다.

환경변수는 [`.env.example`](../.env.example)의 "콘텐츠 시트" 절을 참고하세요.
`MEDIA_SHEET_CSV_URL`을 비워두면 정적 데이터를 쓰므로 로컬 개발에는 설정이 필요 없습니다.

### 캐시

`fetch`에 `revalidate: 600` + `tags: ["media"]`를 걸었습니다.
`/[locale]/*` 는 next-intl 때문에 원래 전부 동적 렌더(`ƒ`)라 페이지 자체는 요청마다 렌더되지만,
시트 조회는 fetch 캐시가 흡수해 10분에 한 번만 나갑니다. EC2에 컨테이너가 하나뿐이라
캐시 일관성 문제는 없습니다.

시트가 응답하지 않을 때 fetch 캐시는 마지막 정상 응답을 계속 내어주므로,
`fromSheet`의 정적 폴백은 실질적으로 **콜드 스타트 시 시트가 죽어 있는 경우**에만 쓰입니다.
(세 경우 모두 프로덕션 빌드로 검증했습니다.)

`revalidateTag`는 Next 16에서 두 번째 인자로 만료 프로파일을 요구합니다. 라우트 핸들러에서는
`"max"`(즉시 만료)가 맞습니다 — 1인자 호출은 deprecated 경고를 내고, `updateTag`는
서버 액션 전용이라 라우트 핸들러에서 예외를 던집니다.

**Cloudflare 프록시(🟠)가 앞단에 있으므로**, 엣지에서 이 경로를 오래 캐시하면
revalidate 후에도 옛 내용이 보일 수 있습니다. 반영이 안 되면 Cache Rules에서
`/*/company/media`의 TTL을 확인하세요.

### 폴백 데이터 갱신

`src/data/media.ts`는 폴백이라 시트와 자동 동기화되지 않습니다.
시트가 충분히 앞서갔다면 CSV로 내려받아 반영하고 커밋해 두는 것이 좋습니다.
(폴백이 오래될수록 장애 시 보이는 내용이 낡습니다.)

## 다음 컬렉션

같은 방식을 넓힐 후보는 **awards → history → papers** 입니다.
전부 평평한 배열이고 자산 파이프라인이 없어 시트로 그대로 옮겨집니다.

넘기지 **않는** 것들:

- `patents`, `certifications` — [`scripts/generate-patent-pages.sh`](../scripts/generate-patent-pages.sh)가
  PDF를 페이지 JPG로 쪼개 S3에 올리고 `cms.ts`의 `generateImageUrls()`가 파일명을 역산합니다.
  시트로 다룰 수 있는 형태가 아닙니다.
- `career`, `companyInfo`, `executives`, `globalBusiness`, `homeStats`, `organization`,
  `products`, `rndProjects` — 콘텐츠가 아니라 페이지 구조에 가깝고, 바뀌는 시점이
  대개 페이지 개편할 때입니다. 관리 UI를 만드는 비용이 내용을 고치는 비용보다 큽니다.

### Payload CMS로 옮길 시점

아래 중 **2개 이상**에 해당하면 [`docs/cms-integration-guide.md`](cms-integration-guide.md)의 재통합 절차를 밟습니다.

- [ ] 시트로 이관한 컬렉션이 5개를 넘음
- [ ] 담당자가 이미지를 직접 업로드해야 함 (URL 붙여넣기로 부족)
- [ ] 4개 로케일 번역을 담당자가 관리해야 함
- [ ] 게시 전 승인·검수 단계가 필요함
- [ ] 시트 오류로 인한 사고가 반복됨
